# 架构审查技能

> 宏观层面分析 Java 项目结构、包组织和依赖方向

## 功能说明

从高层分析项目架构：
- 包组织方式（按层 vs 按功能 vs 六边形）
- 层间依赖方向
- 模块边界与耦合
- 架构反模式（上帝包、贫血领域模型等）

## 使用场景

- "审查这个项目的架构"
- "这个包结构好吗？"
- "检查我们是否遵循整洁架构"
- "查找架构违规"
- 大规模重构之前

## 核心概念

### 包组织策略

| 策略 | 适用场景 | 权衡 |
|------|----------|------|
| 按层分包 | 小型项目，快速启动 | 相关代码分散 |
| 按功能分包 | 中型项目，模块清晰 | 需要共享内核 |
| 六边形架构 | 复杂领域，可测试性 | 更多仪式代码 |

### 依赖方向

```
外层（框架）→ 适配器 → 应用层 → 领域层（内层）

规则：依赖只能向内指向
```

## 使用示例

```
你: 审查这个项目的架构

Claude: [分析包结构]
        [检查依赖方向]
        [识别违规]
        [提供优先级排序的建议]
```

## 检查内容

1. **包结构** - 组织方式、命名一致性
2. **依赖方向** - 领域隔离、无框架泄露
3. **层边界** - 合理的关注点分离
4. **模块边界** - 清晰的 API、封装性
5. **可扩展性** - 功能是否可提取？

## 相关技能
