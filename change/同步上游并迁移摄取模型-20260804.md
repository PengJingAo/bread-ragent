# 同步上游并迁移本地摄取扩展

## 修改内容

1. 保留上游 `Chunk`、`EmbeddedChunk`、`IngestionKernel` 新架构，不恢复已删除的 `VectorChunk` 和旧分块服务。
2. 将关键词索引回灌迁移到 `EmbeddedChunk`：从 PostgreSQL 读取物理 `collection_name`、正文、metadata 和向量，校验并解析 pgvector 文本，同时保留按文档分组、批次写入、docId 兜底和 `fail-on-error` 策略。
3. 统一 PG 数据契约：向量检索、知识库清理和关键词回灌均以 `t_knowledge_vector.collection_name` 物理列为准，metadata 只承担文档与块级扩展信息。
4. 新增 `260804_vector_collection_backfill.sql`，幂等地把历史 metadata 中的有效库名回填到物理列，不删除 metadata、不清空或重建历史向量。
5. 在上游摄取流程中恢复本地异常诊断：分块失败日志记录异常链最底层非空消息，读取对象存储失败时保留原始 cause。
6. 更新 PG 写入与检索测试，新增 PG 清理和关键词回灌测试；同步修正引用提示词测试，使断言与上游当前模板一致。

## 修改原因

上游删除旧 `VectorChunk` 后，本地关键词回灌仍引用旧类型，导致主源码无法编译；同时新写入已使用物理 `collection_name`，本地检索、清理与回灌却继续读取 metadata，可能出现新向量写入成功但无法检索或回灌的问题。本次调整通过适配上游新模型保留本地能力，并用幂等迁移兼容历史数据。
