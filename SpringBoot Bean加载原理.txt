● 所有线索都齐了。你的前提假设有误——这个类其实就在扫描路径下。 下面是完整解释：

  ---
  核心原因：Spring 扫描看的是「包路径」，不是「Maven 模块」

  看这两个关键信息：

  ┌─────────────────────────────┬──────────────────────────────────────┐
  │             类              │                包路径                │
  ├─────────────────────────────┼──────────────────────────────────────┤
  │ RagentApplication（启动类） │ com.nageoffer.ai.ragent              │
  ├─────────────────────────────┼──────────────────────────────────────┤
  │ BIModelProperties           │ com.nageoffer.ai.ragent.infra.config │
  └─────────────────────────────┴──────────────────────────────────────┘

  @SpringBootApplication 的默认扫描规则是：扫描启动类所在的包及其所有子包。

  com.nageoffer.ai.ragent                    ← 启动类在这里
  ├── .infra.config.BIModelProperties        ✅ 子包，能扫到
  ├── .infra.config.AIModelProperties        ✅ 子包，能扫到
  ├── .infra.model.ModelSelector             ✅ 子包，能扫到
  ├── .framework.config.WebAutoConfiguration ✅ 子包，能扫到
  ├── .rag.controller.RAGChatController      ✅ 子包，能扫到
  └── ...所有 com.nageoffer.ai.ragent.**     ✅ 都能扫到

  Spring Boot 完全不关心这个类在哪个 Maven 模块的 jar 
  包里，它只看类加载器能加载到的 class 的包路径是否匹配。

  ---
  常见误解

  很多人的直觉是：

  ▎ ❌ infra-ai 是一个独立的 Maven 模块，跟 bootstrap 分开，所以不在扫描范围内。

  但实际机制是：

  ▎ ✅ Spring 的 @ComponentScan 是基于包路径的，不是基于模块边界的。只要 
  ▎ bootstrap 的 pom.xml 依赖了 infra-ai（通过 Maven 传递），infra-ai 中的 class
  ▎ 就会被加入 classpath，而它们的包路径 com.nageoffer.ai.ragent.infra.* 
  ▎ 恰好在启动类包路径的子树内，所以会被自动扫描。

  如果项目的包命名不是统一前缀，就会扫不到。举例：

  假设 infra-ai 模块的包路径是：
    com.nageoffer.infra.config.BIModelProperties   ← 不是 ragent 的子包

  启动类在：
    com.nageoffer.ai.ragent.RagentApplication      ← 只扫
  com.nageoffer.ai.ragent.**

  此时就扫不到了！必须用以下方式之一解决：

  ┌────────────┬────────────────────────────────────────────────────────────┐
  │    方案    │                            做法                            │

  ├────────────┼────────────────────────────────────────────────────────────┤
  │ Spring     │ 在 infra-ai 的 META-INF/spring/org.springframework.boot.au │
  │ Boot       │ toconfigure.AutoConfiguration.imports 中注册               │
  │ 自动配置   │                                                            │
  ├────────────┼────────────────────────────────────────────────────────────┤
  │ 统一包前缀 │ ✅ 本项目采用了这个方案——所有模块共享                      │
  │            │ com.nageoffer.ai.ragent 前缀                               │
  └────────────┴────────────────────────────────────────────────────────────┘
